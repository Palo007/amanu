Amanu Windows: speed and reliability review

2026-11-06 · branch windows-echo-models · read-only code review plus short web research. Gains are estimates, not measurements.

Baseline (measured)

A 14-minute call with mic and system tracks, on CPU only, with the GPU idle:

  • Echo removal (LocalVQE): 120 s.
  • Transcription (Parakeet Slovak): about 240 s.
  • Total: about 6 minutes.

The freeze after transcription is fixed in 4f1e8e5: the LocalVQE DLL is no longer unloaded.

1. Transcription speed

What the code does now:

  • The two tracks run one after the other: first mic, then system (TranscriptionServices.cs:104-108).
  • Each 60-second chunk starts a new CLI process (:150-159), so the model loads again about 14 times per track.
  • The process runs with --backend cpu and no thread flag (:156), at Idle priority (:232).
  • The Vulkan GPU backend is turned off at build time (Build-LocalRuntime.ps1:40).
  • Echo removal must finish before any transcription starts. But it only changes the mic track. The system track does not need it.

2Set the thread count in each call, and use a higher priority than Idle for batch runs.TranscriptionServices.cs:156, 2320–30%SLow. Other apps on the PC may get slower.

Recommendation: do ideas 1 and 2 first. They are small changes. Then measure, then do idea 3.

2. Speaker detection and naming

Main finding: local engines do not split speakers (no diarization). The whole system track becomes one speaker, "them" (TranscriptionServices.cs:106-107). This is why the table shows results such as 1/2, 1/7 and 0/1.

#IdeaWhereEffortRisk
1Run sherpa-onnx speaker diarization (it has a C# API) on the system track only, so the remote people become "them A", "them B" and so on. One report: 29 minutes of audio in about 3.5 minutes on 4 CPU threads.TranscriptionServices.cs, SpeakerLabels.csMToo many or too few speakers. Set a maximum speaker count. A Windows crash is reported (sherpa-onnx issue 3253).
2Give the naming prompt more context: meeting title and names the user typed. Also accept "medium" confidence when the quote check passes.LanguageServices.cs:327-334, ProcessingPolicy.cs:71SMore wrong names. Keep the quote check.
3Compare quotes without case, punctuation and extra spaces. Today an exact match is required (ProcessingPolicy.cs:73).ProcessingPolicy.cs:73SLow.
4Retry once when the answer is empty or cannot be read. Split long transcripts into parts.ProcessingCoordinator.cs:635-646, LanguageServices.cs:325SOne more model call.

3. Echo and noise removal

  • The echo delay is measured once for the whole file. If the tracks drift apart, or a device changes during the call, nothing follows the change (EchoCancellation.cs:335-356).
  • The fallback works only when there is an exception. If the model runs but makes the mic too quiet during double talk (both sides talking at once), nothing notices.
  • One bad sample (not a finite number) throws away the whole echo pass (EchoCancellation.cs:180).
  • Do not add a general noise remover before transcription. Research found that speech enhancement made Whisper and Parakeet worse in all 40 tested setups (arXiv 2512.17562). A DeepFilterNet issue reports about 20% more word errors.
#IdeaEffortRisk
1Check the cleaned mic track. If it looks worse than the raw mic (for example, too much speech energy lost), use the raw mic.MNeeds a good measure and tests.
2Replace a bad sample with silence and log it, instead of failing the whole pass.SLow.
3Measure LocalVQE with more threads, or split the file into parts that run in parallel, with overlap.MThe model's state breaks at each cut, so check the joins.
4Measure the delay again every few minutes, to follow drift.MMedium.
